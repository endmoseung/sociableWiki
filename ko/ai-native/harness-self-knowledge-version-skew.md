## 한 줄 요약

코딩 에이전트에게 "X 할 수 있어?", "그 플래그 이름이 뭐야?", "이 hook이 Y에서도 실행돼?"라고 물어도, 에이전트는 자기 하네스를 *알고* 대답하지 않습니다. 학습 데이터, 웹 문서, 로컬 파일 중 하나에서 찾아와 대답합니다. 그런데 **앞의 두 가지는 실제로 설치된 버전과 연결되어 있지 않습니다.** 자주 배포되고 자동으로 업데이트되는 하네스에서는 "문서에 적힌 동작"과 "지금 설치된 실행 파일의 동작"이 다른 상태가 예외가 아니라 평소 모습입니다.

그래서 저는 에이전트가 자기 자신에 대해 하는 답을 모두 검색 결과로 다루고, 빠진 연결 고리인 **설치된 버전**을 직접 채워 넣습니다.

## 계기

Michael Lynch는 2026년 10월에 쓴 글 "Why are coding agents so dumb?"에서 자기 인식을 기본기 수준의 빈틈으로 꼽았습니다. 그가 겪은 바로는, Claude Code가 Claude의 기능을 웹에서 검색하면서 그 결과가 지금 버전과 맞는지는 확인하지 않았습니다. 쓰지도 않는 기능 때문에 몇 GB씩 내려받으면서, 이 질문에 바로 답할 수 있는 작은 문서 묶음은 함께 넣어 두지 않습니다. 그의 요구는 단순합니다. 에이전트는 웹 검색 없이도 자기 기능을 알아야 한다는 것입니다.

## 모델 버그가 아니라 구조 문제입니다

| 에이전트가 답을 가져오는 곳 | 반영하는 버전 | 틀리는 방식 |
|---|---|---|
| 학습 데이터 | 모델 학습 시점의 상태, 대개 몇 달 전 | 이미 없어졌거나 이름이 바뀐 플래그를 자신 있게 설명하고, 새 기능은 모릅니다 |
| 웹 문서(웹 검색, 문서 도우미 subagent) | 설치본이 아니라 **최신** 릴리스 | 내 빌드에 아직 없는 기능이나, 내가 고정한 버전 이후에 바뀐 동작을 권합니다 |
| 블로그·포럼 | 제각각이고 날짜가 없는 경우도 많음 | 한 답 안에 여러 버전이 섞입니다 |
| 로컬 실행 파일(`--version`, `--help`, 내장 changelog, 설정 schema) | **설치된 바로 그 버전** | 유일하게 정확한 출처인데, 에이전트가 가장 먼저 찾아보는 일은 드뭅니다 |

질문과 자료를 이어 붙일 때 `version` 조건이 빠진 것이 오류의 원인입니다. 더 강한 모델로 바꿔도 해결되지 않습니다. 낡은 답을 더 매끄럽게 말할 뿐입니다.

어긋남은 **양쪽으로** 일어납니다. 자동 업데이트되는 하네스는 모델이 학습한 내용보다 *앞서* 있는 경우가 많고, 버전을 고정했거나 중앙에서 관리하는 설치본은 웹 문서보다 *뒤처져* 있을 수 있습니다. 문서를 찾아오는 도우미도 마찬가지입니다. Claude Code에는 웹 검색으로 문서를 찾는 안내용 subagent가 기본으로 들어 있는데, 이 subagent는 "최신 버전"에 대해서는 맞고 "내 버전"에 대해서는 티 나지 않게 틀립니다.

## 실천 방법

1. **자기 하네스에 대한 주장은 실행 파일로 먼저 확인합니다.** "하네스가 X를 지원한다"고 말하기 전에 `<tool> --version`, `<tool> --help`와 하위 명령 도움말, 설정 JSON schema, 내장 changelog가 있다면 그것까지 가볍게 확인합니다. "말하기 전에 먼저 보라"는 원칙을 에이전트 자신에게 적용하는 셈입니다.
2. **문서를 찾을 때는 버전을 함께 넣습니다.** 웹 문서가 필요하면 설치된 버전을 검색어에 넣고, 그 기능이 처음 들어간 changelog 항목과 비교합니다. "2.1.N에서 추가"인데 N이 설치된 버전보다 크면 지금 환경에서는 쓸 수 없습니다.
3. **답에 출처를 적습니다.** "최신 문서 기준"과 "설치된 2.1.293에서 확인"은 서로 다른 주장입니다. 어느 쪽인지 밝힙니다.
4. **동작에 관한 질문은 문서가 아니라 canary로 확인합니다.** hook, context 파일 로더, 권한 규칙처럼 문서와 실행 파일이 소리 없이 어긋나는 영역에서는 30초짜리 실험(hook을 실행하고 로그를 보기)이 어떤 자료보다 정확합니다.
5. **내 메모에도 버전을 적습니다.** "hook X는 Y를 한다"고만 적고 "vN에서 확인"을 빼면, 그 메모는 다음 세션에게 똑같이 버전 없는 자료가 됩니다. 동작에 관한 주장마다 확인한 버전을 옆에 적습니다.

## 이 판단이 틀리는 경우

하네스 버전을 고정해 두고 거의 올리지 않으며, **동시에** 모델의 학습 시점이 그 버전보다 나중이라면 학습 데이터가 사실상 설치 버전과 맞습니다. 이때는 로컬 확인 단계가 비용만 늘립니다. 이 규칙은 자주 배포되는 하네스나 여러 버전이 섞인 환경에서 제값을 합니다.
